# ModelContextProtocol (MCP) for BOFH - MVP
 ## Introduction This document outlines the basic commands for interacting with the BOFH toolkit through the ModelContextProtocol. The BOFH (Bastard Operator From Hell) toolkit provides utilities for system administration, file manipulation, and Docker operations. 
 ## MCP Command Structure When working with the BOFH toolkit, commands follow this structure: ``` [MCP] Command: bofh.<module>.<action> Parameters: <parameter1>: <value1> <parameter2>: <value2> [/MCP] ``` 
 ## Basic Command Examples ### Working with the Filesystem #### Analyze Directory Structure ``` [MCP] Command: bofh.filesystem.analyze Parameters: directory: /path/to/target output: /path/to/output [/MCP] ``` #### Create Archive ``` [MCP] Command: bofh.filesystem.archive Parameters: source: /path/to/source destination: /path/to/archive.tar compression: gzip [/MCP] ``` ### Working with Docker #### Visualize Data ``` [MCP] Command: bofh.docker.visualize Parameters: inputData: /path/to/data outputDir: /path/to/output [/MCP] ``` #### Run Analysis Container ``` [MCP] Command: bofh.docker.analyze Parameters: inputDir: /path/to/input outputDir: /path/to/output logDir: /path/to/logs [/MCP] ``` 
 ## Available MCP Tools The BOFH toolkit provides the following tools for interaction: ### Filesystem Management - `bofh.filesystem.analyze` - Analyze directory structure - `bofh.filesystem.archive` - Create archive of files - `bofh.filesystem.find` - Find files by pattern - `bofh.filesystem.copy` - Copy files or directories ### Docker Management - `bofh.docker.build` - Build Docker images - `bofh.docker.run` - Run Docker containers - `bofh.docker.analyze` - Run analysis containers - `bofh.docker.visualize` - Run visualization containers ### System Tools - `execute_command` - Execute a whitelisted shell command - `get_whitelist` - Retrieve the list of whitelisted commands - `add_to_whitelist` - Add a command to the whitelist - `update_security_level` - Update a command's security level - `remove_from_whitelist` - Remove a command from the whitelist - `get_pending_commands` - List commands pending approval - `approve_command` - Approve a pending command - `deny_command` - Deny a pending command
 ## Command Whitelist Guidelines For security purposes, the MCP server implements a command whitelist system. When working with system commands, follow these guidelines: ### Required Whitelist Entries The following commands must be whitelisted for proper operation: ``` # Basic system commands ls # List directory contents pwd # Print working directory echo # Print text to standard output cat # Concatenate and print files cd # Change directory # File manipulation commands mkdir -p # Create directories with parent directories cp -r # Copy directories recursively touch # Create empty files mv # Move files and directories # Git commands git init # Initialize git repository git add # Add files to git staging git commit # Commit changes to git git push # Push changes to remote repository git pull # Pull changes from remote repository git clone # Clone a repository git checkout # Switch branches git branch # List or create branches # Node.js commands npm install # Install Node.js dependencies npm start # Start the application npm run build # Build the application node # Execute Node.js code # Docker commands docker-compose up # Start Docker containers docker-compose down # Stop Docker containers docker build # Build Docker images docker run # Run Docker containers docker ps # List running containers docker rm # Remove containers docker rmi # Remove images docker stop # Stop containers docker network # Manage Docker networks docker volume # Manage Docker volumes # Utility commands curl # Transfer data with URLs grep # Search for patterns in files find # Search for files tar # Create tar archives gzip # Compress files awk # Pattern scanning and processing language sed # Stream editor for filtering/transforming text ```
 ### Whitelist Security Levels When adding commands to the whitelist, use the appropriate security level: 1. **safe**: Commands that are safe to execute without additional review 2. **requires_approval**: Commands that require review before execution 3. **forbidden**: Commands that should never be executed ### Example Whitelist Addition ``` [MCP] Command: add_to_whitelist Parameters: command: "mkdir -p" description: "Create directories with parent directories as needed" securityLevel: "safe" [/MCP] ``` ## Using the Execute Command Tool The `execute_command` tool allows you to run whitelisted shell commands: ``` [MCP] Command: execute_command Parameters: command: "ls" args: ["-la", "/path/to/directory"] [/MCP] ``` For complex commands with many arguments: ``` [MCP] Command: execute_full_command Parameters: command: "find /path/to/directory -name '*.tar' -type f" [/MCP] ```
 ## Best Practices 1. **Work on One Task at a Time**: Complete and validate each task before moving to the next 2. **Validate Results**: Always check that operations completed successfully 3. **Clean Up Resources**: Remove temporary files and Docker resources when done 4. **Command Safety**: Use safe commands when possible, and request approval for potentially dangerous operations 5. **Error Handling**: Properly handle and report errors in executed commands 6. **Careful Cleanup**: Be careful when using commands that can remove files or Docker resources ## MCP Best Practices 1. **MCP stands for ModelContextProtocol**: Always remember what MCP means 2. **Work Methodically**: Focus on one task at a time and validate before moving on 3. **Ask Before New Tasks**: Always ask if a new task is needed before starting it 4. **Show Your Work**: Demonstrate careful execution by showing the validation of each step 5. **Slower Execution is Better**: Taking time to be careful is better than making mistakes ## Error Handling The BOFH toolkit will return error messages for invalid operations or command failures. Always check for errors after executing commands and provide meaningful error information. ## Security Considerations 1. **Directory Access**: Be careful when accessing system directories 2. **Command Whitelisting**: Only use whitelisted commands for security 3. **Docker Safety**: Be careful when managing Docker resources to avoid disrupting the system 4. **Cleanup Operations**: Be extra careful with cleanup operations that remove files or resources 5. **Temporary Files**: Properly manage temporary files and directories The BOFH toolkit operates with the permissions of the executing user, so be careful when executing commands that could modify system resources.
